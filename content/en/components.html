A component

A component is a JavaScript class plus a call to component(Class, meta). The class holds the state (signals) and the methods; meta says what the tag is called (selector), what the template is and which other components it uses (imports).

  • Inputs: fields created with input(initialValue). They are writable signals that the parent fills with [name]="expr" or with a plain attribute (name="text").
  • Outputs: fields created with output(). The child calls emit(value) and the parent listens with (name)="..."; the value arrives as $event.
  • Lifecycle: ngOnInit() (before painting), ngAfterViewInit() (already in the DOM) and ngOnDestroy() (when removed). this.$el is the host element.
  • Methods: they can be passed bare to the template ((click)="save()"): they are already bound to the instance.
Custom tags do not self-close

In HTML always write <ui-card></ui-card>, not <ui-card />: the browser ignores the slash and "eats" whatever follows.

With TypeScript or decorators

@Component({ selector, template }) does the same as component() if your tooling supports decorators. The types (Signal<T>, OutputEmitter<T>, OnInit…) ship with the package: see the reference.

Named slots

The content you put between a component's tags is projected where <ng-content> is. If you need several areas, the component declares <ng-content select="title"> and whoever uses it marks the children with slot="title". Whatever has no slot goes to the default area. The content is evaluated in the parent's scope and stays reactive.

Portals

<ng-portal to="#target"> paints its content inside another element (document.body by default) but keeps it in the component's scope: it is for modals, menus and tooltips that must not get trapped by an overflow or a z-index. It cleans itself up when the block is destroyed. It is in the main package and in runtime-plus.

References to elements

Mark an element with #name and receive it with viewChild('name'): a signal holding the element (or the component instance, if you put it on a component tag) that goes back to null when it leaves the DOM. It is how you focus a field, measure an element or call a method on the child.

Handled errors

If a component defines ngOnError(error, where), it receives the errors from its bindings and handlers and those of the content projected into it. That makes an error boundary: it shows a fallback instead of leaving a hole. Without ngOnError the error is logged to the console and the rest of the view keeps working.

What it catches and what it does not

It catches errors from expressions, bindings and event handlers. It does not catch those thrown in the component's own constructor or ngOnInit: those propagate to whoever mounted it.

Services and dependency injection

inject(Class) returns a shared instance of the class (created on first use): it is for services, global state and API clients. With provide(Class, value) you replace it, for example in a test.

Scoped services: providers

If a component declares providers, the service is its own and its descendants', and every instance of the component has its own. A provider is the class, or { provide: Api, useClass | useValue | useFactory }. inject() looks first at the nearest component that declares it and, if none does, uses the shared instance. It works inside the constructor and field initializers.
